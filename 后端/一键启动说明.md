# 一键启动说明

**推荐用法**：先运行「一键启动」只启动 Milvus，再**单独运行 main.py** 启动 Flask。这样 Apifox 请求正常，关掉 main.py 也不会卡死。

---

## 方式一：PyCharm 里两步启动（推荐）

1. 确保本机已安装并启动 **Docker**。
2. **第一步**：在 PyCharm 里运行 **`start_services.py`**（或运行配置「一键启动 (Milvus + Flask)」）。  
   脚本只会启动 Milvus，等看到「Milvus 已就绪」「请在本项目里单独运行 main.py」即结束。
3. **第二步**：在 PyCharm 里**单独运行 main.py** 启动 Flask。  
   看到 `Running on http://127.0.0.1:5001` 后，用 Apifox 请求即可。关掉运行只停 main.py，不会卡死。

---

## 方式二：只启动 Milvus（不用脚本）

- **Windows**：双击 `start_docker.bat`，等约 1 分钟后在 PyCharm 里运行 `main.py`。
- **命令行**：在「后端」目录下执行：
  ```bash
  docker compose -p catdivide-milvus up -d
  ```
  再运行 `python main.py`。

---

## 为什么之前「一键启动」会卡、关不掉？

之前脚本会用 `os.execv` 把当前进程**替换成 main.py**，相当于「一键启动」进程直接变成 Flask 进程。这时：

- 第一次请求向量接口会加载 CatReID 模型、连 Milvus，可能阻塞十几秒，Apifox 看起来像「进不去方法」。
- 点 PyCharm 的「停止」时，若进程正卡在加载模型或连 Milvus，要等阻塞结束才响应，看起来像卡死。

现在改成：**一键启动只负责起 Milvus，Flask 由你单独运行 main.py**。请求和停止都只影响 main.py，不会和 Docker 脚本混在一起，就不会再卡死。

---

## 停止 Milvus

在「后端」目录下执行：

```bash
docker compose -p catdivide-milvus down
```

---

## 若曾用 VARCHAR 建过向量表

当前 Milvus 的 `cat_id`、`user_id` 已改为 **INT64**（与 MySQL 一致）。若你之前已经建过 collection（当时是 VARCHAR），需要先删掉旧表，应用下次启动时会自动按新 schema 重建。删除方式任选其一：

- **Attu**（Milvus 可视化管理）：连上 `localhost:19530`，找到对应 collection 删除。
- **Python**：在项目目录下执行一次：
  ```python
  from pymilvus import connections, utility
  connections.connect(host="localhost", port="19530")
  utility.drop_collection("cat_vectors")  # 名称以 .env 里 VECTOR_COLLECTION_NAME 为准
  ```

## 依赖说明

- **Docker**：需已安装并已启动 **Docker Desktop**（或 Docker Engine）。  
  **注意**：PyCharm 的「Docker 插件」只是在 IDE 里查看镜像/容器，真正执行 `docker compose` 的是本机的 **Docker 服务**。请先在任务栏打开 Docker 图标，等它完全启动（不再显示 “Docker Desktop is starting…”）后再运行一键启动。
- **MySQL / Redis**：仍使用你本机或现有配置（`.env` 中的 `DB_*`、`REDIS_*`），本 compose 只负责 Milvus。
